# 鸟友、私信和群聊 · 设计与实现合同

2026-11-28，候选0.4.17。[完整英文状态／API／权限合同](en/SOCIAL-0.4.17.md)。本轮优化已有业务功能呈现，不新建第二套云账号／消息数据库。

鸟友分已添加／收到申请／已发申请；收到申请显式接受或拒绝，发出可取消。服务端按账号对及申请者记录状态，禁止自加；无关系→申请→收到／已发→接受后鸟友，拒绝／取消／删除回无关系。重复相同操作在状态符合时幂等，非法跃迁冲突；屏蔽阻止请求和发送并移除关系。

私信从讨论更多→消息或鸟友主页进入。列表、消息历史、发送和已读游标由现有业务提供，接收方可限仅鸟友。发送带稳定操作reference，不确定结果时同内容同reference重试；迟到成功只能清理当时提交的文字，不能擦掉后来输入。账号／页面版本阻止旧回执串号。当前仅文字、前台10秒轮询并在隐藏停止，不宣称WebSocket、后台推送、附件或端到端加密。历史分页时间戳同值的边界，后续需复合游标解决。

群聊：创建者为群主；仅群主邀请互为鸟友者；被邀请不等于已加入。受邀者接受／拒绝，已加入者可离开；群主只能明确确认解散。非成员无历史／发送权限；新成员历史从加入时间开始，屏蔽规则生效。当前仅群主／成员角色、人数上限100及既有限流，不宣称管理员提升、移交、踢人、过期邀请、公开入群链接或群发现。

既有举报／屏蔽／管理路径保持服务端权限。回复和鉴定活动使用现有通知汇总；不公开投票者名单。未来订阅推送需用户明确选择及真实可用模板，本轮没有启用。手帐／草稿／地点书签仍为本机资料，与社区消息存储区分。

本轮视觉矩阵含鸟友／消息／群聊／聊天；自动测试覆盖既有状态、权限、幂等、已读与迟到发送。仍需两个真实账号完整验：申请取消／接受拒绝／移除、仅鸟友私信、双向屏蔽、漏回执重试及新文字、邀请接受拒绝、入群历史边界、离开解散、未读和账号切换。

后续：通知直达收到申请，复合历史游标，申请／邀请历史与过期策略，按需求确定离线重试。富媒体、回执、推送及群管理先确认产品范围。[CloudBase准备](CLOUDBASE-0.4.17.md)仍未启用；现有业务部署见[本轮交接](INTERACTION-0.4.17.md)。
