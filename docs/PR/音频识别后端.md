# PR：音频识别后端（issue #13）

> 分支：`feat/13-audio-recognition` → `main`
> 关联：issue #13「后端声音识别功能」
> 规模：新增 11 个模块文件、8 个测试文件、3 个脚本、7 篇文档；视觉服务代码不改动

## 1. 这个 PR 解决什么

issue #13 要求把第 1 周预研的 BirdNET 实验代码整理成**可部署的正式音频模块**：录完上传、
一次性识别、返回排序候选。本 PR 只做音频这一条线，**不包含**照片识别适配与观察记录持久化
（那部分在并行的 `feat/13-photo-and-observations` PR 中，两者可独立评审）。

预研代码（`鸟类识别预研/experiments/*`、Tkinter 测试台）保持原样不动，正式模块不复用其 GUI
与脚本入口，只复用已验证的推理路径与参数结论。

## 2. 接口一张图

```text
POST /api/v1/audio/analyses   (multipart/form-data)
  audio=<MP3|WAV|AAC(ADTS)|M4A>   top_k?   client_reference?
        │
        ├─ 准入：≤10 MB、上传 20 s、并发 1 + 排队 4（超出 429）
        ├─ 暂存：私有临时文件，边写边计数
        ├─ 校验：Content-Type 别名（26 个）+ 魔数嗅探 + 族内一致性
        ├─ 解码：ffmpeg → 48 kHz 单声道 float32
        ├─ 分窗：3.0 s 窗 / 1.5 s 步进，末尾补零
        ├─ 推理：BirdNET v2.4（LiteRT/XNNPACK，串行）
        ├─ 聚合：逐标签取跨窗最大分、过滤 8 个非鸟类类别、要求跨窗确认
        └─ 对齐：AviList v2026（学名精确 → 唯一英文名 → 保留原始标签并标 unmapped）
        │
        └─ 200 {state: candidate|unknown, candidates[], model, audio, policy, timing, notes, diagnostics}
```

关键约定（详见 [`docs/音频识别后端/API.md`](../音频识别后端/API.md)）：

- `state=candidate` 有候选；`state=unknown` 推理成功但无可靠候选（**不是错误**）；
- 服务失败走统一错误信封（`{"error": {code, message, request_id, details}}`）；
- 候选字段：物种 ID、学名、中英文名、分数、`score_type=birdnet_confidence`、`confirming_windows`、
  `mapped`（未映射时 `species_id=null`，保留 BirdNET 原始标签）。

## 3. 阈值与短录音规则（用样本检查后确定，不是拍脑袋）

预研只给了“0.5 阈值 + 三窗两确认”的方向，本 PR 用 32 个样本（5 种鸟 × MP3/AAC/WAV +
5 个 2 s 片段 + 人声/车流/风噪 × 4 格式）做了扫描：

| min_score | 最少确认窗 | 鸟声 top-1 | 负样本误报 | `unknown` |
|---:|---:|---:|---:|---:|
| 0.25 | 1 | 18/20 | 2/12 | 12 |
| 0.50 | 1 | 18/20 | 1/12 | 13 |
| **0.50** | **2** | **18/20** | **0/12** | 14 |
| 0.70 | 2 | 18/20 | 0/12 | 14 |

→ 采纳 **0.5 + 跨窗 2 窗**。风噪样本单窗最高 0.642（Flammulated Owl），正是被跨窗确认拦下的，
关掉确认就会误报——这是本 PR 最重要的一个结论。

短录音（<3 s）补零为 1 个窗口，跨窗确认自动降为 1，并在 `notes` 写明
`short_clip_zero_padded` / `reduced_window_confirmation`；最低可识别时长设为 1.0 s
（预研中 0.5 s 会“错得很有信心”）。

## 4. 变更清单

| 路径 | 说明 |
|---|---|
| `backend/src/bird_audio/audio.py` | 上传暂存、容器嗅探、ffmpeg 解码、临时文件清理 |
| `backend/src/bird_audio/windows.py` | 3 s 分窗、补零、确认窗数 |
| `backend/src/bird_audio/labels.py` | 标签解析、非鸟类过滤、物种目录对齐 |
| `backend/src/bird_audio/analyzer.py` | 聚合、排序、拒识（纯函数，无 I/O） |
| `backend/src/bird_audio/engine.py` | BirdNET LiteRT 引擎 + mock 引擎 + 资产哈希校验 |
| `backend/src/bird_audio/service.py` | 准入/并发/超时/取消编排，产出报告 |
| `backend/src/bird_audio/api.py` `schemas.py` `app.py` `config.py` `metrics.py` `cli.py` | HTTP 层、配置、就绪检查、指标、命令行 |
| `backend/src/bird_common/` | 应用外壳（请求 ID/错误信封/CORS）、API Key 鉴权、JSON 日志、物种目录加载 |
| `backend/tests/test_audio_*.py` `test_common.py` | 169 个音频相关用例 |
| `backend/scripts/prepare_audio_samples.py` | 把预研素材转成小程序录音格式 + manifest |
| `backend/scripts/evaluate_audio.py` | 真实模型跑样本 + 阈值扫描，输出 eval 报告 |
| `backend/scripts/smoke_audio_service.py` | 对运行中的服务发真实 multipart 请求，产出联调证据 |
| `docs/音频识别后端/` | 说明、API、部署、模型语义、验证报告、验收检查表、OpenAPI 快照、前端 mock 样例 |

依赖变更：新增可选 extra `audio = [ai-edge-litert, imageio-ffmpeg, numpy]`，新增
`bird-audio` 入口。**没有改动 base 依赖**，视觉/业务环境不受影响。

## 5. 验证证据（可在本分支复现）

| 项 | 结果 | 位置 |
|---|---|---|
| 单元 + 接口测试 | 音频相关 169 个用例通过；全仓覆盖率 92%+ | `pytest` |
| 真实模型样本验证 | 鸟声 top-1 18/20（10 s 全对 15/15），负样本误报 0/12 | [`validation/audio-eval.md`](../音频识别后端/validation/audio-eval.md) |
| 真实 HTTP 联调 | 32 个样本全部 200；8 个错误用例全部命中预期错误码 | [`validation/integration-evidence.json`](../音频识别后端/validation/integration-evidence.json) |
| 端到端耗时 | p50 178 ms / p95 193 ms（10 s 音频，6 窗；解码 ~45 ms，单窗推理 ~20 ms） | 同上 |
| 容量 | 12 并发 → 5 通过、7 个 429；临时目录无残留 | VALIDATION §6 |
| AAC 复测 | ADTS/M4A/CRC 变体与 26 个 Content-Type 别名全通 | VALIDATION §9 |

复现命令：

```bash
cd backend
python -m pip install -e '.[test,audio]'
export BIRD_AUDIO_ENGINE_BACKEND=birdnet
python scripts/prepare_audio_samples.py
python scripts/evaluate_audio.py
bird-audio --port 8100 &
python scripts/smoke_audio_service.py --base-url http://127.0.0.1:8100
```

模型权重（49 MB，CC BY-NC-SA 4.0）不入库，按 [`MODELS.md`](../音频识别后端/MODELS.md) 恢复；
生产必须配置模型/标签 SHA-256，启动时会重算并拒绝不一致。

## 6. 建议的评审顺序

1. `docs/音频识别后端/README.md`（10 分钟看完全貌与边界）
2. `docs/音频识别后端/API.md` §2（契约、限制、错误码）

7. `docs/音频识别后端/VALIDATION.md`（数据与结论）

## 7. 与另一个 PR 的关系

- `bird_common/` 同时出现在两个 PR 中，内容完全一致（共享基础层），合并时不会冲突。
- `backend/pyproject.toml`、`backend/.env.example`、`backend/README.md`、
  `.github/workflows/vision-backend-ci.yml` 两个 PR 各加了本模块的段落，位于相邻位置，
  建议**先合本 PR，再合照片+观察记录 PR**（后者 rebase 一次即可，冲突均为“两边都保留”）。
- 本 PR **不改** `bird_vision` 任何文件；视觉服务的重构（改用 `bird_common`）在另一个 PR 中。
