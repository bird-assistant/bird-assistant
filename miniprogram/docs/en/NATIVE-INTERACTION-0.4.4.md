# Map, navigation and photography fixes · 0.4.4

25 November 2026 · [中文](../NATIVE-INTERACTION-0.4.4.md)

User feedback rejects native acceptance of 0.4.3: zoom still needed a pan, circles overlapped, the expected pull animation was absent, and navigation eventually stopped. The earlier passing source tests remain historical evidence, not proof of correct native behavior. This iteration addresses SRS MAP-01/02, COM-02, ID-01 and LIVE-01.

| Area | Resulting behavior |
| --- | --- |
| Navigation | The old unconditional pushes could exhaust WeChat's ten-page stack silently. Related read-only details now reuse existing destinations or replace the current read-only page at depth 9, reserving one slot for event-channel pickers. Editors and unsent replies/messages stay in the stack. Failures show feedback and do not retain a navigation lock. Tests visit 120 destinations and cover retry, drafts and picker channels |
| Native lifecycle | Hidden maps unmount their native surface and overlays, stop timers and invalidate asynchronous results; returning remounts and restores the viewport. Existing camera release/pause remains |
| Zoom | Uses the native event's scale/region/center, including end events without begin or drag. A visible-only 240 ms viewport observer also detects API-only zoom changes; gesture sampling remains. Native callbacks have an 1800 ms deadline. Latest responses win, and an unchanged failed query is not automatically hammered |
| Clusters | A Mercator screen-distance pass combines colliding server grid cells, retaining counts and geographic bounds.40 px circles have a 4 px gap. Each render starts from server cells, so zoom can split prior display groups. Rotation/overlooking are disabled. Coincident coordinates stay grouped rather than being displaced to invented locations. Large labels show the actual count |
| Drawer | The shell reaches the Tab boundary. The translucent panel has a 42 px upward content fade, scrolling tail room, and a 24 px clear native-attribution footer. Tencent marks remain readable; permission to hide them was not established. Header explains newest collection/publication/import first; row dates are observation dates. Actual database order is created DESC, id DESC |
| Icons and refresh | Drawn line chevrons replace typed arrow characters. The feed uses a bounded scroll-view with a custom refresher: birds during pulling, a release prompt at threshold and flight while refreshing. Late requests cannot clear a newer refresh. Pagination, button refresh, retry and reduced-motion handling remain. Page JSON changes require a full compile |
| The two test posts | Read-only public API inspection shows two different IDs: the 24 November 18:06 post shares a date, device and map copy; the 17:21 post does not. Nothing was deleted or deduplicated by image. Publication time and observation date are labeled separately |
| Related records | A discussion and a map contribution are independently published copies of one observation. Links name that relationship. Private points open at zoom 17, public 1 km grids at 13, other public regions at 11, with precision labels. A rounded public center is never described as the original photo point |
| Photography | Cards support available lens, original resolution, WB, EV, metering and flash data in addition to focal length, aperture, shutter and ISO. The loaded display-copy resolution is labeled separately. Upload extraction stays allowlisted; no GPS, serial numbers or guessed vendor AF modes |
| Optional author settings | Compose and preview offer camera, lens, resolution, ISO, shutter, aperture, focal length, AF, WB, EV, metering, lighting and flash fields. Drafts retain them. Author input and file-derived data use separate cards; unknown fields stay absent |
| Existing-server compatibility | Clearly labeled human-readable caption appendices carry optional settings through the existing posting API. New clients render them as cards; older clients can read the text. File data is included only with sharing selected. No unsupported JSON fields are sent to the old preview endpoint. The combined 2000-character limit is validated before publication. Backend changes add richer EXIF extraction and camera sharing for standalone discussion photos; deployment is still separate |
| Camera space | Zoom and visual/audio clues have independent compact handles, tap/swipe expansion and short fade/slide transitions. Live/recording status remains visible. The actual zoom response, bounded 3.5× shortcut, horizontal ruler, fine controls, shutter, import and review remain |

Validation: client `npm run verify` passes 151 tests. Local backend passes 467 tests with 55 skips and 85.36% coverage; the changed community suite passes 17 tests and Ruff passes. The local Python 3.12 development environment does not replace target deployment locks; current-head CI checks those separately. Nine source projections at 320/390/768 widths use original illustrations. Their print renderer cannot prove native layer order, touch, safe areas or device acceptance.

Native acceptance still requires pinch-only splitting/merging,20+ related visits, actions after repeated Tab switches, actual pull/release, sparse EXIF and manual settings, location precision and independent camera folding. Compile once for changed page JSON. SDK authentication/network errors, canary/preload/worker diagnostics remain visible and are not claimed fixed by UI changes.

Live Qwen, real publishing/reply moderation, coordinated cloud deployment and broader device adaptation remain next. Journal refinement stays deferred. Fade, slide and dissolve remain later visual priorities; this iteration uses restrained, reduced-motion-aware transitions.
