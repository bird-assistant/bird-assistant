# 地图、论坛与相机交互 · 0.4.3

2026-11-25 · [English](en/NATIVE-INTERACTION-0.4.3.md)

本轮按最新设备截图与反馈改客户端交互。以当前 SRS 的 MAP-01/02、ID-01、LIVE-01、COM-02 为基础；数字仍表示观察记录数，不表示鸟只数。延续现有视觉会话、素材复核、私人保存、公开脱敏与认证边界。

| 反馈 | 本轮行为 |
| --- | --- |
| 单条记录过早变成定位针 | 查询缩放级别小于16时，单条也显示数字1圆点；16及以上才显示单记录针，多记录仍是数字圆点 |
| 缩放后必须再拖动才更新 | 原生 begin/end 的顶层和 detail 事件均处理；移动期间每160ms采样视野，渲染通知采用固定窗口节流，不再反复推迟读取；结束后30ms读取最终区域 |
| 圆点点击无反应或很慢 | 取消加载期间的全局点击屏蔽。点击立即改变视野或打开带加载状态的记录面板；标记携带其原有筛选快照与独立ID，桥接交接期间保留上一帧目标 |
| 列表过高，底部有色块 | 手机浮动列表最多300px且不超过地图高度的46%，底部圆角和列表内渐隐；面板下方保留36px原生署名区。开关列表不再改变原生地图尺寸 |
| 拖动会把列表关闭 | 列表在手势开始时缩成标题条，保持打开；新视野独立更新聚合与记录。稳定后的新记录返回才恢复展开；用户主动收起的面板继续收起 |
| 更多工具使用微信原生样式 | 改为应用自己的圆角工具面板、图标与副标题；保留资料库、外部鸟讯、找鸟友、消息、群聊和本机草稿入口 |
| 刷新缺少视觉提示 | 顶部刷新按钮内三只小鸟错峰飞过；保留下拉刷新与错误重试。动画只在请求进行时出现，支持减少动态效果偏好 |
| 拍摄设备只是一行文字 | 照片下增加设备卡与焦距/光圈/快门/ISO徽章；仅使用服务端已允许返回的字段，没有的数据不补写；隐藏设备名称末尾的内部型号代号，不改原记录 |
| 识别页丢失原有层次 | 恢复半透明双页签线索面板、较小的开启/停止按钮、倍率快捷点和快门区，保留实际实时视觉与高清照片分析 |
| 变焦刻度需要上下滑动开合 | 在倍率区上滑展开、下滑收起，横滑连续变焦；方向锁防止上下手势误改倍率，保留轻触开合与±0.1微调 |

地图聚合与列表使用独立请求代次，过期响应不能覆盖新区域或重开已关闭的面板。组件隐藏/卸载后停止手势采样、清理计时器并忽略迟到结果；记录分页去重与防重入保留。读取失败有显式重试，不将渲染回调变成无限重试源。

已修复论坛 Page 初始选项里的 `new Set()`：互动锁移到按页面实例索引的 WeakMap，避免 DevTools 的非简单自由数据克隆警告。没有屏蔽其他日志。

设备可用倍率以 `camera.initdone.maxZoom` 和 `CameraContext.setZoom` 返回的实际值为准。识别到 Pura 70 Pro+ 名称时使用1/2/3.5/5/10快捷点；未知型号保留3和3.5两个点，仍按实际范围裁掉不可用值。3.5只代表倍率请求，**不宣称强制切换物理镜头**。微信锁定的5.2.3类型合同没有厂商闪拍/快门速度/镜头选择选项；拍高速主体可用系统相机闪拍后导入原片，界面提供这一建议，没有伪造闪拍开关。

验证：`npm run verify` **140通过，0失败、0取消、0跳过**。重点覆盖纯缩放与连续渲染、乱序响应、加载中点击、列表缩小/恢复和手动收起、原生读取失败/重试、3.5倍及实际倍率回报、上下/左右手势分流、自定义菜单路由、独立互动锁与稀疏EXIF。后端源码与依赖锁未变；不沿用0.4.2的旧CI作为本头结果。

另生成320/390/768宽的7种源码布局投影，使用原创示例图，非用户截图。[评阅板](design/interface-0.4.3.png)和[布局读数](design/interface-0.4.3-bounds.json)可复查。`npm test`后运行 `node scripts/review-interface.mjs` 与 `python scripts/render-interface-review.py`；打印渲染器的可选依赖为 WeasyPrint68、Pillow、PyMuPDF，不加入应用依赖。投影不模拟原生摄像头、地图层级、触摸、透视缩放或安全区；部分原生组件/打印flex读数不可作为像素验收证据。

设计参考：[SmugMug官方照片EXIF信息面板](https://www.smugmughelp.com/hc/en-us/articles/18212410328596-Display-a-photo-s-EXIF-information)，借鉴照片与信息分层，不复制其照片或界面资源。平台合同核对：[微信官方类型仓库](https://github.com/wechat-miniprogram/api-typings)及本项目安装的5.2.3类型文件；腾讯平台[相机](https://www.tencentcloud.com/zh/document/product/1219/57744)与[地图](https://www.tencentcloud.com/zh/document/product/1219/57775)资料仅作辅助核对，不用其他平台的合同替代微信实机能力。

仍需在已存在的微信工程与真机验收：连续捏合时的事件节奏、快速点圆点、边拖边缩列表、原生署名与Tab安全区、Pura 70 Pro+的实际倍率/镜头路由、前后台切换、录像长按、实时模型与导入原片。截图中SDK鉴权/网络失败与渲染层空拒绝不能用布局修改宣称已解决；应用自己的读取失败已覆盖，SDK原因仍需实际配置和网络排查。
