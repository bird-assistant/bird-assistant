> 目标：用图形界面快速确认「视频 / 屏幕区域 / 音频」三条链路都能跑，且数字与报告一致。
> 一页纸，逐条打勾即可；勾选状态可在 GUI 的「验收清单」页一键导出。

## 2. 屏幕区域（tab：屏幕区域）

| # | 检查项 | 怎么做 | 通过标准 | ✔ |
|---|---|---|---|---|
| 2.1 | 框选交互 | 点「框选屏幕区域…」，拖拽一个矩形 | 出现青色选框；松开后按钮旁显示 `(x,y) 宽×高`，且与肉眼所见一致（高 DPI 下也应一致） | ☐ |
| 2.2 | 实时识别 | 把一段鸟的视频/图片放在选区里，点「开始」 | 选区内容出现在预览区并出框；状态栏 FPS ≥ 5 | ☐ |
| 2.3 | 更换选区 | 停止 → 重新框选另一块 → 开始 | 新选区生效，无残留旧画面 | ☐ |
| 2.4 | 延迟 | 看 `p50 / p95` | 与同参数视频模式同量级（±20%） | ☐ |
| 2.5 | 自遮挡提示 | 观察是否把预览窗口自身也框进去 | 若框进去会出现「自己看自己」的框；移开窗口后消失 | ☐ |

> 说明：屏幕采集是**按选区原样抓取**，不做缩放；选区越大推理越慢（yolo11n 按 imgsz 缩放，但抓屏与拷贝开销随面积上升）。

## 7. GUI 已知限制

1. **只做单帧/单流**：不含录播导出；要保存标注视频请用 CLI（`experiments/run_visual_baseline.py`）。
2. **屏幕采集含窗口自身**：选区若覆盖本窗口，会把自己也框进去。
3. **多显示器**：选区使用虚拟桌面坐标，跨屏框选可行，但预览会按选区原始尺寸抓取，超大选区会掉帧。
4. **物种词表仍是 ImageNet-59**：候选名是"最像的雀形目"，不是真实物种（这是模型选型问题，见 [visual-findings.md](visual-findings.md) §7）。
5. **音频模型固定 3 s 输入**：窗长选项只是"给多少真实音频"，不足部分补零。
6. 无 GPU 加速：本机 `torch.cuda.is_available()=False`。
