# 羽迹 · 地图、鸟种资料库与讨论实施设计

设计提案，面向小程序、业务后端、内容编辑和测试同学。基线为团队小程序 0.3.0、本地已接入的视觉识别、地图 PR #17 的提交 `1ae7354`。下文接口标为「沿用」的是已有合同，标为「新增」的是待开发合同。

## 1. 用户从哪里进，做完回哪里

沿用五个 Tab。建议第四个 Tab 从「讨论」改名「社区」，首页仍打开地图。社区顶部分为「鸟种资料库」和「鸟友讨论」。从底栏进入时恢复上一次栏目，从识别、地图点进来的用户直接到相应详情页。

| 用户此时想做什么 | 操作路径 | 返回时的状态 |
| --- | --- | --- |
| 出门前看看附近有什么鸟 | 首页地图 → 搜公园或浏览附近 → 点标记 → 地点卡 → 某条公开鸟讯 → 查看鸟种资料 | 回到同一条鸟讯，再返回保留地图视野、日期和鸟种筛选 |
| 拍完想知道自己认得对不对 | 识别复核 → 点目标②旁候选的「查资料」→ 对照识别特征和相似种 → 返回，再点「确认」或「待鉴定」 | 回到原照片、原目标和候选列表。候选与用户确认分别记录 |
| 认不出来，想请人帮忙 | 私人观察 →「请鸟友鉴定」→ 选择要公开的照片和文字 → 预览 → 发布 → 收到带理由的物种建议 → 作者决定是否采纳 | 帖子保存社区意见，采纳动作只更新作者选中的观察目标，并留下更正历史 |
| 只想分享公园里见到了某种鸟 | 我的观察 →「发布到地图」→ 选择公开范围、时间精度和署名 → 看公众视角 → 发布 | 「我的 → 发布管理」单列地图鸟讯和讨论帖，各自有预览、状态、更新、撤回 |

在识别页先保留照片和本机观察，再允许进入资料或发帖页。跨页只传 `speciesId`、本机观察 ID 和目标 ID 等引用。发帖页通过当前账号的本机草稿取用户选择的素材，私人照片路径、坐标和令牌留在路由参数之外。识别页返回后先恢复草稿，实时相机由用户重新开启。

## 2. 地图与地点卡

**首页布局。** 顶部保留搜索框和「日期／鸟种／范围」，地图占主体。右下角设「定位」，拖动后出现「搜索此区域」，避免手指一移动就重刷结果。底部收起时显示所选地点、最近观察日期和可见记录数，上拉展开地点卡。标记用不同形状和文字区分「公开鸟讯」「我的位置记录」「多条记录」，聚合数字的单位用「条」。放大字体或点位密集时，底部「看列表」可访问同一批结果。

**地点卡。** 首屏展示地点名称、可公开的地理范围、到达条件及来源。下方「最近鸟讯」按观察时间排序，每条同时显示鸟名或「待鉴定」、观察日期、来源、公开范围。详情再显示更新时间。时间未知单列，来源停止更新时显示最后更新时间。有地点但没有鸟讯时仍能浏览地点、收藏或发起观察。收藏默认私人。需展示署名的公开打卡另作显式操作。用户拒绝定位后沿用上次视野或手选城市，搜索、拖动、筛选均可用。

**数据接法。** 从 #17 移植原生 `map`、视野读取、地点适配器、手动选点页和服务测试，接入 `miniprogram/miniprogram/pages/home`。保留现有首页的搜索、筛选、面板和返回行为。`map-model.ts` 的示例百分比坐标只用于演示。现有项目对地图供应商和试点城市存在两套约定，首版建议先用 #17 的腾讯地点适配。供应商和试点地区由服务端配置，首批验收用团队已取得资料授权的一个城市。第三方地点搜索只提供地点和地址，地图上的鸟讯来自已批准的公开贡献或具有展示授权的来源。

**位置输入和查询。** 私人观察允许当前定位、照片位置、手动选点、位置未知四种输入，记录来源与坐标系。选点页取消时保留原表单。公开视野查询与展示使用 `GCJ-02`，原始 `WGS84` 及转换记录留在受控存储。公开查询先按发布策略生成的展示坐标过滤和计数，防止通过缩小查询框反推精确位置。只有区域名的鸟讯可在获准的区域列表显示，隐藏位置的记录不返回可定位标记。外部媒体、地名和来源的许可随数据入库。

## 3. 社区信息库 · 鸟种资料

资料库首页提供中文名、学名、别名搜索，首版从已校对词条进入。物种详情也支持从模型的稳定 `species_id` 直达。共用一份名录和版本，中文名缺失时回落到有来源的英文名或学名。先录入一组真机能识别、团队能校对的常见鸟，逐步增加图文覆盖。

| 详情区块 | 用户看到的内容 | 实施方式 |
| --- | --- | --- |
| 首屏辨认 | 中文名、学名、参考图、两三条看得见的辨识特征 | 编辑审核特征和图片出处。从识别页进入时，可切换看自己的拍摄原图，仅自己可见 |
| 容易混淆 | 相似种及关键区别，可逐项对比 | 编辑维护物种 ID 之间的关系。缺图时显示文字与来源 |
| 公开观察 | 明确地区、时间范围、资料来源的鸟讯，可点「在地图看」 | 查询与当前物种关联且可见的地图副本，地图打开时带入物种筛选 |
| 鸟友讨论 | 该物种的鉴定求助、经验和回复 | 查询已发布且显式关联该物种的帖子。候选关联在求助帖上标「待鉴定」 |

发布词条前校验素材授权、署名、资料来源和编辑版本。名录里有该物种但没有图文时，返回基础名称卡，显示「辨识资料待补充」，用户仍能回到照片或发起求助。社区回复供作者和编辑参考，正式词条更新走编辑审核。

### 3.1 同一张鸟种卡从三个入口打开

识别候选行、地图鸟讯里的鸟名、讨论帖里的物种标签使用同一个紧凑入口，显示鸟名、当前语境和打开详情的箭头。识别候选旁标「可能是」，求助帖标「正在讨论」，地图鸟讯标观察日期。点击后打开同一物种详情页，使用稳定的 `species_id`。实时画面的跟踪编号仅用于选中镜头里的目标。缺少可解析名录 ID 的目标保留「待鉴定」和「查找鸟种」入口，手动查阅也允许返回原目标。

| 从哪里点 | 打开时优先显示 | 保留的返回位置 |
| --- | --- | --- |
| 照片目标的候选名 | 「辨认」及本机原图对照，点击「返回复核」后再确认 | 本次素材、目标编号、候选序列 |
| 地图鸟讯卡的鸟名 | 「出现地点」，沿用地图的区域和日期，标出刚才查看的地点 | 地图视野、筛选、选中地点与底部卡片。聚合标记先展开记录供选择 |
| 社区帖子里的物种标签 | 「讨论」，显示当前帖关联标记和其他已公开帖子 | 原帖子及阅读位置。从社区资料库搜索进入则默认打开「辨认」 |

详情顶部固定中文名、学名、代表图和「辨认／出现地点／讨论」三个页签。首屏用一行可点的摘要提前展示当前范围内有公开记录的地点数和观察记录数。从识别进入时保留「我的照片」与「参考图」切换。页内切换保留所选地区和时间，帖子若按地点筛选，只采用其明确公开的地点。

### 3.2 出现地点和社区内容如何对应

「出现地点」提供区域选择、近 30 天／近一年／全部时间、地点列表与小地图。首版建议无上游筛选时默认上次手选区域、近 30 天，首次无选区则显示「全部收录地区」。地点行列出可公开地名、最近观察日期、独立记录数和来源。点击某行打开该地点、该物种的公开记录，点「展开地图」保留物种、范围和时间。全图返回后仍在同一行。零结果提示「该范围和时段暂无公开观察」，可清除日期或扩大区域。历史整体分布资料若后续引入，另行标注资料来源、年代和覆盖范围。

| 社区或观察动作 | 鸟种详情中的变化 |
| --- | --- |
| 拍摄、保存私人观察或查资料 | 本人在复核页可对照自己的照片。公开地点统计只读取获准公开的地图副本 |
| 将已辨明的观察发布到地图并通过审核 | 按公开地点汇入「出现地点」，可从地点行查看有时间和来源的记录 |
| 发帖询问「可能是黄腹山雀吗」 | 黄腹山雀的「讨论」出现一条标为求助的帖子。地点统计等待观察者确认并另行发布地图鸟讯 |
| 一条观察同时发地图和讨论 | 地点计一条观察，讨论计一篇帖子。地图副本和帖子的授权互相独立 |
| 撤回地图贡献或讨论帖 | 该渠道对应的列表和计数随撤回更新。同一公园还有其他公开记录时保留该地点行 |

后端建议增加 `GET /api/v1/species/{id}/places`，接收区域、观察日期和游标，返回 `place_count`、`record_count`、地点行及每行的 `place_id`、公开标签、最近观察日期、记录数、来源。统计使用与地图相同的公开记录查询，对物种、可见性和时间先过滤，再按可公开地点分组，以不同的来源观察标识计数。同一张图有两个同种目标仍计一次观察。仅能公开至区域的记录在区域级展示，隐藏的精确地点不参与分组。讨论通过 `GET /api/v1/posts?species_id=…` 独立分页，保留「作者确认」「讨论候选」的关联角色。缺少百科正文时仍展示名录名称和可用的两个栏目。

验收可使用一条同时发布到地图和社区的模拟观察。分别从照片、地图和帖子打开同一鸟种，核对鸟名、各自的起始页签、返回位置，再撤回地图副本，检查出现地点计数更新、讨论帖仍可打开。

## 4. 鸟友讨论与发布预览

**列表和详情。** 沿用现有帖子卡片、编辑器、回复与书签控件。列表提供「全部／鉴定求助／观察分享」和按物种筛选，首版按发布时间倒序。卡片显示帖子类型、标题、经许可的缩略图、署名、发布时间、回复数。帖内回复按时间正序、按游标翻页，保留发言上下文。鉴定回复可选「我认为是某物种」，并填写区别特征。普通回复只写文字。作者可撤回自己的帖子或回复，点赞和书签可撤销。书签进入「我的收藏」，不计入个人物种数。

**发帖。** 从社区点「写帖子」可写纯文字。从观察进来默认生成本机求助草稿，作者勾选允许展示的照片、鸟种标签、时间精度和地点范围，可编辑标题、正文，再选署名或匿名。默认隐藏位置，匿名、位置是两个独立控件。预览直接使用服务端准备的公开副本，明确这次将公开哪些字段。用户取消则回草稿，发布遇到弱网保留输入。用双击、超时重试同一请求测试，最终只生成一帖。

**状态与治理。** 列表只展示审核通过的内容。作者能在「我的发布」看到草稿、待审核、已发布、需修改、已撤回。图文和回复均进入审核流程，首版可以用人工队列。提供举报入口、限频、审核理由、复审和管理员操作日志。更新已发布内容时保留上一个已批准版本，新版本审核通过后替换。作者撤回优先于任何待完成审核，撤回后原链接、列表、聚合和媒体授权同时失效。已有书签显示「内容已撤回」。

### 4.1 外部社区数据接入与羽迹社区运营

地图和鸟种详情增加来源筛选「全部／羽迹鸟友／外部记录」。打开外部观察时展示观察日期、公开地点范围、发布机构或应署名的作者、数据集、许可、最近同步时间和原记录入口。详情底部放「在羽迹讨论这条记录」，点开创建本地帖子草稿，附一张只有已获准字段的来源卡。原帖正文、评论、媒体和作者账号分别按合作授权处理。用户自己的发言、审核和撤回由羽迹管理。

| 首批来源 | 接入方式 | 小程序呈现 |
| --- | --- | --- |
| GBIF 收录的观鸟数据集 | 先按试点地区查询有人观察、明确出现、位置可用的鸟类记录。正式批量导入用带 DOI 的下载，保存原始数据集、标识和推荐引用。首版选 CC0 与可正确署名的 CC BY 记录 | 鸟种的历史出现地点、地图来源卡。分别标出观察日和更新日 |
| 本地观鸟社、学校社团或已有论坛 | 与数据提供方约定 API 或 CSV 交付、可用字段、署名、媒体权利、位置精度、更新和撤回联系人。已有文章可由原作者授权精选转载或投稿，授权不足时使用获准的来源链接 | 记录进入地图，署名文章进入「合作内容」。本地回复显示在羽迹讨论串里 |
| 羽迹用户 | 私人观察显式发布地图鸟讯或在讨论页求助，分别预览、审核和撤回 | 地图标记「羽迹鸟友」。求助或回复注明候选与建议，确认后可由作者单独选择贡献地图 |

GBIF 的网络涵盖多种许可，批量下载支持 DOI。iNaturalist 的观察、图片和声音可分别授权。记录入库时保存权利人与许可，媒体按单件检查，编辑图鉴仍需单独择图。官方依据见 [GBIF 许可](https://www.gbif.org/terms)、[GBIF 下载与 DOI](https://techdocs.gbif.org/en/data-use/api-downloads)、[GBIF 引用规范](https://www.gbif.org/citation-guidelines) 和 [iNaturalist 许可设置](https://help.inaturalist.org/en/support/solutions/articles/151000173511)。

**后台同步。** 阿里云业务服务器定时把数据导入暂存区，按来源配置校验许可与展示字段，映射版本化的 `species_id`，按上游精度及本地敏感策略生成公开位置。仅到区县的记录汇入区县。不能确定物种或地点的条目交给编辑。用 `(source, external_id)` 幂等更新，另存 `dataset_key`、`occurrence_id`、原链接、引用、许可、来源修改时间和同步批次。同一记录经两个平台到达时按原始 ID 或可验证的同源关系合并出处。缺少可靠标识时分来源列数并提示可能重合。按批次对账，完整快照中确认撤回或接到合作方通知后下架并重算地点汇总；短暂网络故障保留最后一次成功结果和日期。现有视觉服务的 GBIF 地区／月份候选缓存继续用于识别，公开展示另从有逐条出处的数据生成。

**社区日常维护。** 试点由一位编辑管理来源、词条与图片授权，一位版主管求助帖、举报、敏感地点和撤回请求，技术维护人看同步日志、备份和恢复。小团队可以兼任。邀请本地社团成员分享自己的观察，首批内容用真实活动记录和鉴定问题开场。每周优先处理无人回答的求助、重复记录与来源更正。运营看真实提问数、得到有依据回复的比例和首次回复时间。外部观察条数单独统计。

**首版验收。** 用一条获准的外部观察走通「鸟种 → 地点 → 查看来源 → 发起羽迹讨论」。再用另一账号回复，验证帖子与来源卡可独立查阅。模拟来源撤回后，地图与计数下架，讨论保留本地原创文字并显示「引用记录已撤回」，原引用附件停止显示。羽迹作者删除自己的帖子时，外部来源仍依它自身的授权和同步状态展示。

## 5. 业务服务与存储

微信小程序经 `api.auroraliu.cn` 的 Nginx 调用阿里云 `bird_business`。微信登录、用户权限、私人观察、媒体、地图、资料库、帖子和审核由此服务负责。GPU 容器负责视觉推理。GPU 暂停时，地图浏览、资料阅读、发帖和已有观察的发布独立可用。

现有业务层包含微信登录、按身份隔离的 `/api/v1/observations`、FastAPI 和 SQLite WAL。旧创建接口要求 `source_analysis_id`、物种 ID、学名，会为缺失时间填入当前时间，并按用户、分析、物种去重。新客户端要支持未知时间、待鉴定、一张照片两只同种鸟。建议新增一组版本化的私人观察接口，保留旧客户端语义。将既有云记录用带来源的映射迁入新模型，历史时间的可靠性无法还原时标「来源未核实」。上线前核对迁移后的归属和条数。

| 表或集合（建议名） | 核心字段和约束 |
| --- | --- |
| `observations_v2`、`observation_subjects`、`identification_history` | 所有者、本机 UUID、版本、拍摄时间与精度、上传时间、私有位置及来源、媒体引用。每个目标有独立 ID，分存模型候选及版本、用户选择、采纳历史。唯一 `(owner, client_id)` |
| `species`、`species_articles`、`species_relations`、`places` | 名录 ID、别名和版本。词条正文、图片许可、编辑状态。相似种对及区别。地点来源、展示区域、访问说明和更新时间 |
| `media_assets`、`public_media` | 私有原件归属、本地引用对应的云端 ID。公开图绑定渠道、发布版本和审核状态。由服务端校验文件类型、解码尺寸和大小，重编码清理 EXIF/GPS 并生成缩略图 |
| `map_contributions`、`publication_previews` | 私有来源引用仅内部使用，公开副本 ID、授权字段、展示范围、展示坐标、策略与版本、状态。预览绑定用户、渠道、来源版本、策略版本和期限 |
| `posts`、`post_species`、`replies` | 类型、作者、独立的公开文本和媒体、关联物种、状态、批准版本。回复可含建议物种和理由。帖子附件使用自己的副本 |
| `reactions`、`bookmarks`、`reports`、`moderation_events` | 每人每对象每操作唯一。举报状态、操作者、对象版本、处理时间和理由。书签私有，编辑、审核和普通用户权限分开 |

首版在现有业务机使用 SQLite 事务与版本化迁移。给公开鸟讯建立 `(status, species_id, observed_at, id)` 索引及展示位置空间索引或网格索引，帖子按 `(status, published_at, id)` 排序，回复按 `(post_id, created_at, id)` 排序。空间范围要在分页前过滤。上线前用试点数据回放视野查询和同时写回复的负载，再决定是否迁移 PostgreSQL/PostGIS。私有媒体放在公网静态目录外，线上可接私有对象存储。下载经业务层鉴权。公开媒体按渠道和版本授权，撤回时停止签发、清缓存。如需即时阻断旧链接，由媒体网关逐次校验发布状态。

## 6. 前后端合同

下表以公网路径为准。地图读合同沿用 #17 的驼峰字段，其他新接口建议沿用 FastAPI 现有蛇形字段。前端在服务层归一化。涉及所有权的请求从已有微信会话提取身份。当前 `MobileAuth` 在业务服务只许可 observations 路径，新增访问策略与 Nginx 业务路由要一起交付。公开只读可匿名。`scope=mine/all`、写操作、私有媒体与「我的」要求登录。编辑和审核另验角色。

| 模块 | 接口 | 关键合同 |
| --- | --- | --- |
| 登录、旧观察，沿用 | `POST /api/v1/vision/auth/wechat`，`/api/v1/observations` | 复用现有短期 Bearer 会话、错误体和请求号。把小程序登录抽到共用客户端 |
| 私人观察，新增 | `POST/GET /api/v2/observations`，`GET/PATCH/DELETE /api/v2/observations/{id}` | 新建上传本机 UUID、多目标与可空时间/物种。响应返回 ID、版本和同步状态。更新带预期版本 |
| 地图读，沿用拟议合同 | `GET /api/v1/map/observations`，`GET /api/v1/map/observations/{id}` | 四个视野边界、`coordinateSystem`、`scope`、`startDate/endDate`、`speciesId`、`cursor/limit`。返回 `items, nextCursor, total` 和调用者有权限的展示字段 |
| 地点，新增 | `GET /api/v1/places?q=…`，`GET /api/v1/places/{id}` | 搜索或查看地点、来源和更新时间。地点可在鸟讯接口增加可选 `placeId` 过滤。搜索服务不可用时保留已授权缓存 |
| 资料库，新增 | `GET /api/v1/species?q=…`，`GET /api/v1/species/{id}` | 支持中文、别名、学名。返回基础名录、图文状态、相似种、来源/许可及版本。关联鸟讯、帖子各自分页 |
| 媒体与公开预览，新增 | `POST /api/v1/media`，`GET /api/v1/media/{id}`，`POST /api/v1/publication-previews` | 上传私有文件需身份。预览提交来源、所选字段、渠道、公开精度、署名、附件。返回 `preview_id`、实际将展示的副本及到期时间 |
| 地图发布，新增 | `POST /api/v1/map/contributions`，`PATCH/DELETE /api/v1/map/contributions/{id}` | 创建与更新提交地图渠道的 `preview_id`，删除撤回。作者变更私人鸟名后选择是否重新预览更新公开副本 |
| 讨论，新增 | `GET/POST /api/v1/posts`，`GET/PATCH/DELETE /api/v1/posts/{id}`，`GET/POST /api/v1/posts/{id}/replies`，`DELETE /api/v1/replies/{id}` | 列表按类型及 `species_id` 过滤。发帖或编辑使用帖子渠道的预览。回复可附 `suggested_species_id` 及理由 |
| 采纳建议，新增 | `POST /api/v2/observations/{id}/subjects/{target_id}/identifications` | 提交 `reply_id`、所选物种与预期版本。校验观察所有者、回复可见性和关联目标，在同一事务追加历史并更新当前选择。作者随后决定是否更新已发布副本 |
| 互动和管理，新增 | `PUT/DELETE /api/v1/posts/{id}/like`、`…/bookmark`，`GET /api/v1/me/publications`、`…/bookmarks`，`POST /api/v1/reports`，`GET /api/v1/moderation/queue`，`POST /api/v1/moderation/decisions` | 按最终状态设置互动。作者查各渠道状态。管理员按对象版本处理。书签保留失效占位 |

**地图合同细节。** `minLatitude/minLongitude/maxLatitude/maxLongitude` 为展示系边界，跨日期变更线时分两段查询再去重。日期为上海时区的首尾包含日期。`speciesId=__unknown__` 查待鉴定。`scope=mine` 查本人私有标记。`scope=all` 合并可见公开副本与本人的私人标记，使用不同标记类型。与 #17 一致，首版每页 60 条、前端最多加载 300 条，聚合显示「已加载 N 条」，区域 `total` 只计调用者在筛选条件下可见的记录。同一查询使用稳定排序和游标，换视野清游标并丢弃晚到响应。私人图层使用独立的账号缓存，退出账号清理。

**一次发布的请求顺序。** 用户点「发布到地图」后，若观察仅在手机，则先询问并同步所需观察和选中的附件。失败保留本地草稿。假设用户选择公开「公园范围」和日期，匿名署名，服务端先校验所有权、敏感地点/物种策略以及媒体状态。前端画出服务端实际允许的范围，请用户确认。随后用该预览和稳定请求键提交，收到 `pending_review` 时显示「已提交审核」。审核通过后才进入他人的地图。无地点可选的用户能保存私人观察和发讨论。完全隐藏位置时不产生地图点，界面提示改发无位置讨论。

**写入和撤回。** 创建、发布、回复接受 `Idempotency-Key`，服务端以调用者、操作、键和请求摘要约束重复写入。同键不同内容返回 `409`。更新需校验版本。来源或策略在预览后改变要求重新预览。列表读取、缩略图、详情和计数均以当前可见性为准。匿名展示移除内部用户标识、个人主页入口和精确位置引用。公开投影同时检查缩略图、附件、文字地名及元数据。私有原件删除前展示仍在线的副本供用户逐项选择，按选项事务执行。撤回一个渠道只失效该渠道的记录和媒体。

**失败反馈。** `401` 单次刷新微信会话后以原请求键重试。`403` 提示权限不足。无查看权的对象与已撤回对象对第三方统一返回 `404`。`409` 提示重新预览或处理版本冲突。`413` 提示选较小图片。`422` 定位至具体字段。`429/503` 保留输入并允许稍后重试。公开读取失败时显示缓存时间或重试入口，未获结果与「查询成功、当前区域 0 条」使用不同文案。

### 公开副本示例

以下为模拟响应。用户选择匿名发布公园范围的鸟讯，服务端返回公众将看到的字段。客户端用 `display` 原样渲染预览，「确认发布」按钮只提交预览编号，服务端从已保存的预览生成副本。

```json
{
  "preview_id": "preview_demo_01",
  "channel": "map",
  "display": {
    "species_name": "黄腹山雀",
    "identification": "observer_confirmed",
    "observed_date": "2026-11-24",
    "time_precision": "date",
    "place_name": "示例公园",
    "location_precision": "park",
    "public_name": "匿名鸟友",
    "media": []
  }
}
```

浏览者 B 只能读取该渠道批准的展示字段。作者 A 的「发布管理」额外显示审批和撤回操作。审核人可以处理待审副本，按角色授予访问权限。按物种或地点跳转时，社区和地图继续使用同一套公开查询与可见性检查。

| 顺序 | 小程序交付 | 后端交付 | 可当场验收的结果 |

小程序可沿现有 `pages/home`、`pages/community`、`pages/profile` 和识别复核页分工，新增普通分包页或子页面承载物种、地点、帖子详情与公开预览。保留一个应用入口。业务端在 `backend/src/bird_business` 内按地图、名录、讨论和发布拆路由，复用现有身份、错误体、指标和数据库配置。部署配置对应 `backend/deploy/course/bird-api.nginx`。新前缀指向业务端口 `8200`，视觉推理继续使用现有隧道。按功能开关逐项开放，先验证公网与真机，再开放公开写入。

真机验收用 A、B 两个普通账号与一个审核账号，覆盖定位拒绝、未知日期、同图两只同种鸟、连续拖动地图的乱序响应、公开和私人筛选、两种渠道的四种发布组合、匿名含图片、发布中断重试、撤回和审核并发、资料缺页、第三方限流、举报及审核权限。敏感位置逐一核对 HTTP 响应、详情、聚合、媒体元数据和分享预览。运维观察地图和词条查询延迟、第三方失败率、发布重复率、审核队列积压和撤回生效时间。日志仅保留请求号和必要状态。
