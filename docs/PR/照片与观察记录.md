# PR：单张照片识别适配 + 观察记录持久化（issue #13 的两个外部依赖）

> 分支：`feat/13-photo-and-observations` → `main`
> 关联：issue #13「另由你跟进两个外部依赖：单张照片识别适配和观察记录持久保存」
> 规模：新增 1 个视觉适配模块、1 个业务服务、10 个测试文件、3 篇文档；
> 视觉实时链路的行为不变（只把重复实现改为复用共享层）

## 1. 为什么需要这个 PR

前端要完成「拍照识别 → 确认候选 → 保存观察记录」，而后端原先只有**会话式实时识别**：

- 拍照页只需要一次识别，不需要建会话、传帧、订阅 WebSocket；
- 识别结果没有任何地方可以落库，观察记录无家可归。

本 PR 补上这两块，且刻意让它们与音频服务**共用同一套响应结构、错误信封与鉴权规则**，
前端只需一套 mock 与错误处理。

## 2. 新增能力

### 2.1 `POST /api/v1/vision/analyses` —— 单张照片一次性识别

复用同一个 YOLO 检测器与 BioCLIP 物种 Provider，不做会话、不做跟踪、不写库：

```http
POST /api/v1/vision/analyses
Content-Type: multipart/form-data

image=<JPEG/PNG/WebP>
```

```json
{
  "analysis_id": "pho_…",
  "state": "candidate",
  "candidates": [
    {"rank": 1, "species_id": "avibase-F2858F9F", "scientific_name": "Egretta garzetta",
     "common_name_zh": "白鹭", "common_name_en": "Little Egret",
     "score": 0.93, "score_type": "relative_similarity", "similarity": 0.412}
  ],
  "subjects": [{"rank": 1, "bbox": {"x1": 0.24, "y1": 0.18, "x2": 0.76, "y2": 0.82},
                "state": "candidate", "reason": "candidate_above_similarity"}],
  "model": {"name": "bioclip-2-zero-shot", "backend": "open-clip", "device": "cuda:0", "ready": true},
  "image": {"width": 1280, "height": 960, "size_bytes": 231231},
  "policy": {"decision": "candidate", "reason": "candidate_above_similarity", "max_subjects": 3},
  "timing": {"decode_ms": 8.1, "detection_ms": 45.2, "species_ms": 120.4, "total_ms": 173.7}
}
```

- 取面积/置信度最高的前 N 个目标（`BIRD_VISION_PHOTO_MAX_SUBJECTS`，默认 3）分别分类；
- 状态：`candidate` / `unknown`（`no_bird_detected`、`subject_below_minimum_size`、
  `species_backend_disabled`、分类器自身的拒识原因）；
- 错误码与帧上传一致：`EMPTY_IMAGE`(422)、`IMAGE_TOO_LARGE`(413)、`UNSUPPORTED_IMAGE_TYPE`(415)、
  `IMAGE_DIMENSIONS_INVALID`(413)、`IMAGE_DECODE_FAILED`(422)、`UPLOAD_TIMEOUT`(408)、`AUTH_*`(401)；
- 与实时管线共用 `max_concurrent_inference` 信号量，不会和视频流抢爆 GPU。

文档与样例：[`docs/视觉识别后端/API.md`](../视觉识别后端/API.md) §2.1、
[`mock/photo-analysis-candidate.json`](../视觉识别后端/mock/photo-analysis-candidate.json)。

### 2.2 `bird_business` —— 观察记录持久化（默认端口 8200）

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/observations` | 保存用户确认的候选；同一 `(analysis_id, species_id)` 重试返回 200 + 同一条记录 |
| `GET` | `/api/v1/observations` | 分页查询（`limit`/`offset`/`source`），只返回当前凭证的记录 |
| `GET` | `/api/v1/observations/{id}` | 单条查询；非本人记录返回 404（不泄露存在性） |
| `DELETE` | `/api/v1/observations/{id}` | 删除自己的记录 |

- 存的是**确认后的观测**（物种、来源分析、时间、经纬度、备注、当时的模型分数），
  **不存**原始音频/图片；
- SQLite + WAL，`--workers` 强制为 1；换成外部数据库只需替换 `db.py`；
- 生产必须关闭匿名并配置 `BIRD_BUSINESS_API_KEYS`。

文档：[`docs/业务后端/README.md`](../业务后端/README.md)。

### 2.3 共享基础层（`bird_common`）与视觉服务重构

`bird_common` 提供应用外壳（`X-Request-ID`、统一错误信封、CORS）、API Key 鉴权、JSON 日志、
AviList 目录加载。视觉服务原先各自的实现改为委托它：

| 文件 | 变化 | 对外影响 |
|---|---|---|
| `bird_vision/errors.py` | 复用 `bird_common.errors.ServiceError`，保留 `NotReadyError`/`SessionNotFoundError` | 无（错误码/状态码不变） |
| `bird_vision/auth.py` | 复用 `bird_common.auth.ApiKeyAuth` | 无（含会话所有权逻辑不变） |
| `bird_vision/logging.py` | 复用 `bird_common.logging` | 无（多记录 `analysis_id` 等字段） |
| `bird_vision/app.py` | 中间件/异常处理收敛到 `bird_common.app_factory.build_service_app` | 无（路由、CORS、错误体一致） |
| `bird_vision/inference/species.py` | `Taxon` 与 `load_catalog` 改为从 `bird_common.catalog` 导入，删除重复实现 | 无（同名校验逻辑一致，测试覆盖） |

> 视觉服务**已有接口与行为不变**是硬要求，因此本 PR 保留原有 `test_api.py`/`test_sessions.py`/
> `test_species.py` 等既有用例作为回归证据，未修改其断言。

本地复现：

```bash
cd backend
python -m pip install -e '.[test]'
pytest tests/test_photo_analysis.py tests/test_business.py tests/test_common.py
BIRD_VISION_DETECTOR_BACKEND=mock BIRD_VISION_SPECIES_BACKEND=mock bird-vision --port 8000
curl -sS -X POST http://127.0.0.1:8000/api/v1/vision/analyses -F "image=@image/任意.jpg;type=image/jpeg"
bird-business --port 8200
```

真实 BioCLIP 候选需要 GPU 环境（`.[gpu]`）；本 PR 的接口验证使用 mock 后端，
形状与真实响应一致，GPU 侧的验收仍按 `docs/视觉识别后端/DEPLOYMENT.md` 执行。

  **完全一致**，合并不会冲突。
- `backend/pyproject.toml`、`backend/.env.example`、`backend/README.md`、
  `.github/workflows/vision-backend-ci.yml` 各自只加本模块的段落，位置相邻；
