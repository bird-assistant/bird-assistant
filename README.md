2026软工项目组！做一个观鸟助手

## 当前实现

- 第 1 周视觉与音频可行性预研：[即时鸟类识别](docs/即时鸟类识别/识别技术预研-README.md)
- 可部署视觉后端：[backend](backend/README.md)
- 视觉后端架构与接口：[视觉识别后端](docs/视觉识别后端/README.md)
- 完整需求规格说明书：[Markdown 源文件](docs/需求规格说明书/羽迹观鸟助手_软件需求规格说明书_V1.1.md) / [提交版 PDF](docs/需求规格说明书/羽迹观鸟助手_软件需求规格说明书_V1.1.pdf)

视觉后端已经提供实时会话、图片安全校验、鸟体检测、会话级跟踪、BioCLIP 2、AviList v2026 全球 11,172 种名录、未知鸟拒识、GBIF 当地列表严格优先与低相似度全球回退、最新帧背压、WebSocket、鉴权、指标和自动化测试。地区与出现次数不修改模型原始相似度；只有当地列表没有视觉可用候选时才使用全球模型。物种候选仍需使用本地鸟类评测集完成准确率与阈值校准验收，不能把模型原始分数称为正确率。

感谢大家参与观鸟助手项目的开发！我是组长刘景程。

以下是一些公告，会不时更新：

1:项目统一使用github管理，微信群则用于临时沟通和提醒、约时间，希望大家不要错过相关消息。云文档暂时都放在/docs下，有需要再用腾讯文档之类的工具

2:我会创建issue，然后在Projects下的看板中发布（当然也可以在Issues直接看到）。包括但不限于：产品调研；需求分析；具体功能（前后端）；测试；部署；写文档。我会指派issue的负责人，给出截止时间，具体要干什么，如果对issue有疑问直接v我。

3:每次完成任务更新一下看板状态和文档，大家主动维护文档，可以自由添加修改（最好不要删除）云文档。看板状态从TODO：还没做，In Progress：在做了，In Review：做完了还没审，Done：结了；如果进度卡住在看板上注明并联系我，然后找其他组员或者我协助。

4:代码分支：任何人都不要直接在 main 上开发，也不要直接向 main 强制推送代码。main分支是保存核验过的代码的。

开始新任务前：
- 更新本地 main；
- 从最新 main 创建任务分支；
- 在任务分支中开发；
- 完成后发起 Pull Request；
- 评审和自动检查通过后再合并。

推荐分支命名统一为：
- 新功能：feat/Issue编号-简短名称
- Bug 修复：fix/Issue编号-简短名称
- 文档：docs/Issue编号-简短名称
- 技术实验：spike/Issue编号-简短名称
- 重构：refactor/Issue编号-简短名称

commit也建议添加以上前缀

5:PR审阅：每次提交一个PR一定要在本地做好测试再交，自己写好测试程序，然后把测试的详情结果也交上来。开会的时候商量一下谁来审阅PR，审阅PR到底是严格重复测试一遍还是看两眼给过，详细内容留待讨论。发现bug提交成issue并更新看板

6:暂定每周开一次线上短会交流迭代情况，我会做会议纪要留档。具体要做怎么样的观鸟助手还没有清晰的认知，在会上我们要详细讨论。

7:其他：修改别人负责的模块前，先通知相关负责人；工作量明显不平衡时及时联系我；代码、调研、设计、测试、评审、部署和文档都属于项目贡献；不要把敏感信息，比如apikey、密码、.env文件、令牌提交到仓库中。

8:推荐使用wsl开发（Linux最好的发行版），里面可以用code，可以谷歌如何在wsl里面使用梯子和codex，如果在windows里开发做好跨平台。
