# 视觉识别后端：架构与系统边界

## 1. 结论

当前仓库已经从“桌面端模型预研”增加为“可部署的实时视觉推理服务”。生产拓扑采用公网业务服务器与 GPU 推理服务分离：

```text
微信小程序摄像头
  │  2～5 FPS JPEG；视频预览留在手机
  ▼
公网业务网关（2 vCPU）
  ├─ 用户登录、会话权限、限流
  ├─ HTTPS / WebSocket 稳定域名
  ├─ 观测记录与业务数据库
  └─ GPU 不可用时的降级策略
  │
  │  内部 HTTPS/WSS；不传平台密钥
  ▼
云 GPU 视觉服务（本次实现）
  ├─ 图片校验与解码
  ├─ YOLO 鸟体检测
  ├─ 会话级轨迹维护
  ├─ 最佳鸟体裁剪选择
  ├─ 任意经纬度 + 拍摄月份的 GBIF 候选过滤（离线优先，实时缓存兜底）
  ├─ BioCLIP 2 + AviList v2026 候选排序
  ├─ 相似度/歧义拒识（无地区加分）
  ├─ 最新帧背压
  └─ 指标、日志和健康检查
```

小程序不直接持有 GPU 服务的长期 API Key。正式环境由公网业务网关调用 GPU 服务；课程联调时可以临时通过平台 HTTPS 端口访问，但仍必须开启鉴权。

## 2. 为什么不是上传视频文件

用户本地摄像头保持正常预览帧率，识别端只采样 2～5 FPS。检测结果通过 WebSocket 更新；短暂漏检时后端继续返回外推轨迹框，已通过门控的鸟名在一次拒识或待确认切换期间保持稳定。因此系统是实时摄像头识别，不是“选文件上传识别”。

后端不尝试处理每秒 30 帧：这样会浪费带宽与 GPU，并在网络抖动时形成无法追上的旧帧队列。

## 3. 单帧处理流程

```text
上传图片
  ↓ 字节数 / MIME / 解码尺寸检查
Pillow 解码与 EXIF 方向修正
  ↓
YOLO 仅检测 bird 类
  ↓
当前会话的 ByteTrack 分配 track_id
  ↓
轨迹是否连续出现至少 N 帧？
  ├─ 否：tentative，只返回鸟框
  └─ 是
      ↓
鸟体短边是否达到 64 px、裁剪是否优于上次或已经到达定期复检时间？
  ├─ 否：waiting_for_quality
  └─ 是
      ↓
是否有可用的当地 GBIF 候选？
   ├─ 否：使用全球 BioCLIP 排名
   └─ 是：同时计算当地候选与全球 BioCLIP 排名
       ├─ 当地 Top-1 达到最低相似度：保留当地排名，并在当地列表内接受或歧义拒识
       └─ 当地 Top-1 低于最低相似度：使用全球模型结果
      ↓ GBIF 出现次数不参与打分
相似度与 Top-1/Top-2 间隔是否同时过阈值？
  ├─ 否：unknown，可附候选供复核
  └─ 是：candidate，仍不自动确认为用户记录
```

## 4. 会话和背压

每个会话拥有独立 ByteTrack，防止不同用户的视频互相污染。检测模型与分类模型在进程内共享，因为权重很大；只允许一个推理任务进入 GPU。ByteTrack 会使用低置信检测维持轨迹，但不包含外观 ReID，两只鸟严重重叠或长时间遮挡后仍可能交换 ID。

请求在 multipart 解析和图片解码前执行鉴权、会话所有权、帧率、并发上传和最坏情况内存预算检查。Pillow 解码在线程执行；每会话最多一个上传，解码后图片、排队图片和最佳裁剪均有全局内存上限。

同步模型推理超过配置时限后，运行时立即转为 not-ready，但不会尝试取消无法安全停止的原生线程。服务会等该线程真正返回后再释放图片、轨迹和模型；编排层可据 `/readyz` 摘除流量，必要时在进程退出超时后由容器强制回收。

实时 GBIF 查询在独立的有界工作池中执行，不占用 GPU 推理槽，也不计入模型推理时限。实时会话创建后立即预取当前月份；批量历史图片可通过缓存准备接口先准备全部月份，再开始识别。查询直接分页读取 `scientificName` 分面，不再逐个请求物种详情。完成和明确空结果保存在云端 SQLite，默认 30 天、最多 2,048 个区域查询，跨会话和服务重启复用。

GBIF 当地列表拥有严格优先级。当地 Top-1 原始相似度达到 `BIRD_VISION_SPECIES_MIN_SIMILARITY` 后，不再比较全球候选；Top-1/Top-2 过近时在当地列表内返回 `unknown`。只有当地 Top-1 低于最低相似度，或当地记录不可用/不足时，才使用全球模型排名并返回相应 `fallback_reason`。

每个会话的待处理队列长度固定为 1：

- 新帧到达时 GPU 空闲：立即处理；
- GPU 忙且队列为空：保存这一帧；
- GPU 忙且队列已有旧帧：旧帧被新帧替换，并发送 `vision.frame.dropped`；
- 排队时间超过限制：丢弃为 `stale_in_queue`。

这是实时视频正确的背压策略。实时界面需要“最新状态”，不需要把已经过时的每一帧都处理完。

## 5. 状态语义

### 轨迹状态

| 状态 | 含义 |
|---|---|
| `tentative` | 刚出现，尚不足以证明是稳定目标 |
| `confirmed` | 连续匹配达到配置帧数，可以进入物种分类门控 |

`track_id` 只表示一次会话内的短期画面轨迹，不是鸟的永久身份，也不能直接作为观察到的鸟只数量。
测试报告中的“确认鸟体”只统计 `confirmed`；“原始轨迹”包含 `tentative` 和短暂丢失轨迹，仅用于诊断检测/跟踪，不应解释为鸟只数量。

### 鸟种状态

| 状态 | 含义 |
|---|---|
| `unavailable` | 没有配置经过审核的物种分类模型和目录 |
| `waiting_for_quality` | 已发现鸟，但轨迹、尺寸或清晰度不足 |
| `unknown` | 已执行分类，但相似度过低或候选太接近，拒绝强猜 |
| `candidate` | 模型已经给出候选，但尚未由用户或专家确认 |

## 6. 数据和隐私

当前服务：

- 不持久化上传帧；较大的 multipart 请求可能由 ASGI 框架短暂溢出到操作系统临时文件，请求结束后关闭并由系统回收；
- 不在日志中记录图片内容、API Key 或完整请求体；
- 只在内存保留待处理的最新帧和短期轨迹状态；
- 会话关闭或空闲超时后清理跟踪状态；
- 经纬度不是必填字段；首次实时 GBIF 缓存未命中时，坐标会编码在按查询半径生成的多边形中，月份作为查询条件发送到 `api.gbif.org`。持久缓存保存哈希区域键和聚合物种计数，不保存原始经纬度，但仍按位置派生数据管理；可关闭实时查询以停止该外部传输；
- 拍摄时间只用于选择月份窗口；时间来源不可靠时必须标为 `unknown`，系统会使用当地全年集合，避免伪造精度。

如以后保存原图用于用户记录、专家复核或模型训练，必须把三种用途分别征得授权，不能因为用户保存了一次观测就默认获得训练许可。

## 7. 当前边界

- 预研确认 YOLO11n 能检测 `bird`，不能直接识别具体物种；
- 旧 ImageNet-59 分类器词表不覆盖项目鸟种，生产服务完全不使用它；
- AviList v2026 全球目录已接入；中文名覆盖不是全球 100%，缺失时回退英文名/学名；
- BioCLIP 2 的 `relative_similarity` 是本次候选空间内的相对分数，默认拒识阈值尚未在项目实拍集上校准；
- 仓库附带合肥中心 100 km 的 GBIF 月度出现记录作为可选离线缓存；默认不假设照片来自合肥或中国。其他任意地区会按坐标实时查询 GBIF，生产环境可再构建并审核离线网格以降低延迟和外部依赖；
- YOLO 模式使用每会话独立 ByteTrack，但没有外观 ReID，严重交叉和长遮挡仍需真实视频评测；
- 音频 BirdNET 不在本服务内，后续作为独立服务和证据来源；
- GPU 真机吞吐和准确率需要在云容器上完成验收，仓库不会虚构尚未测得的数字。

## 8. 扩容方式

单 GPU 使用一个进程。需要扩容时：

```text
业务网关
├─ session A → GPU worker 1
├─ session B → GPU worker 2
└─ session C → GPU worker 1
```

会话创建后，所有帧和 WebSocket 事件必须粘性路由到同一个 Worker。不要使用普通随机轮询把同一会话分散到多个模型进程。
