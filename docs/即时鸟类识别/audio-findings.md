# 音频线结论：能不能从录音里快速返回可能的鸟种

> 数据截止：2026-10-22。CPU（4 线程）推理，明细见 [results/audio/sweeps.md](../results/audio/sweeps.md)。

## 1. 一句话结论

BirdNET v2.4 在普通 CPU 上**单窗推理 17.2–17.9 ms（p50，3 s 窗）、p95 ≤ 25 ms**；干净录音 **5/5 段 top-1 正确**（置信度 0.90–1.00）。
**1 秒音频就够用**（5/5），0.5 s 掉到 3/5。
噪声不会让 top-1 变错，但会把置信度打下来：风噪 0 dB 时从 0.95 掉到 0.58；**单独的低频交通噪声会直接误报（0.47 的 Manx Shearwater）**。
→ 结论：**先走服务端**；产品阈值必须 ≥0.5，并配 VAD + 连续窗确认。

## 2. 模型与运行时

| 项 | 值 |
|---|---|
| 模型 | BirdNET v2.4 Global 6K，FP32 TFLite，**49.3 MB** |
| 类别 | 6522（含 `Human vocal` 等非鸟类标签，可用来排除人声） |
| 输入 | 固定 **144000 样本 = 48 kHz × 3 s**，单声道 float32 |
| 动态窗长 | **不支持**。实测 0.5 s 输入会在计算图内抛 `CONCATENATION` 维度不匹配；短音频必须补零到 3 s |
| 输出 | 6522 维 logits → flat sigmoid → 每类 0–1 分 |
| 运行时 | LiteRT (`ai-edge-litert`) + XNNPACK，4 线程，CPU |
| 设备 | Intel Core Ultra 9 275HX / Windows 11 / Python 3.13（与视觉线同一台） |

> 关于依赖：官方推荐的 `birdnetlib` 在 Windows + Python 3.13 上跑不起来（`pydub` 依赖已移除的 `audioop`、且要外部 ffmpeg；TFLite 加载器还会被中文路径卡住）。本项目直接用 LiteRT 加载模型字节，绕开整条链路，见 [birdnet_runtime.py](../experiments/birdnet_runtime.py)。

## 4. 结果

### 4.1 一次识别需要多长音频（干净音频，hop = 窗长/2）

| 窗长 | top-1 命中 | 说明 |
|---|---|---|
| 0.5 s | **3/5** | 乌鸫→Eastern Bluebird(0.92)、大山雀→White-throated Fantail(0.80)，错得很自信 |
| 1.0 s | **5/5** | 置信度 0.94–0.99 |
| 2.0 s | **5/5** | 置信度 0.92–1.00 |
| 3.0 s | **5/5** | 置信度 0.90–1.00 |

→ **"至少 1 s、推荐 3 s"**。0.5 s 的危险在于**错得很有信心**，不能靠置信度兜底。

### 4.2 噪声注入（3 s 窗，SNR = 20 / 10 / 5 / 0 dB，5 段鸟鸣边际统计）

| 噪声 | 20 dB | 10 dB | 5 dB | 0 dB | 平均置信度（干净→0 dB） |
|---|---|---|---|---|---|
| 人声 | 5/5 | 5/5 | 5/5 | 5/5 | 0.954 → **0.695** |
| 车流 | 5/5 | 5/5 | 5/5 | 5/5 | 0.954 → **0.911** |
| 风噪（合成） | 5/5 | 5/5 | 5/5 | 5/5 | 0.954 → **0.582** |

- **top-1 一次都没错**，但置信度单调下降；风噪影响最大（频谱宽、掩盖高频鸣声）。
- 车流虽响，但能量集中低频，对识别干扰反而小 —— 与直觉相反，值得写进产品说明。
- 置信度下降意味着**阈值策略必须随噪声自适应**，否则要么误报要么永远不提示。

### 4.3 负样本（完全没有鸟）

| 片段 | 最高分 | 命中类别 | ≥0.25 误报 | ≥0.5 误报 |
|---|---|---|---|---|
| 人声 | 0.044 | `Human vocal` | 否 | 否 |
| 车流 | **0.471** | Manx Shearwater | **是** | 否 |
| 风噪 | **0.253** | Flammulated Owl | **是** | 否 |

→ 单靠 0.25 阈值会有误报；**0.5 阈值 + 三窗中两窗超标**才稳。人声被正确标成 `Human vocal`，可作为"排除人声"信号。

### 4.4 延迟

| 指标 | 值 |
|---|---|
| 单窗推理 p50 | 17.2–17.9 ms（不同音频差异 <1 ms） |
| 单窗推理 p95 | 17.7–25.3 ms（首窗含分配，偶发 25 ms） |
| wav 读取（10 s） | 7–9 ms（一次性） |
| 10 s 音频（6 窗）总耗时 | ≈ 110 ms |

## 5. "实时"到底能做到多快

| 形态 | 能做到 |
|---|---|
| 流式监听 | 3 s 窗 + 1.5 s 步进 → **每 1.5 s 出一次结果**，推理仅占 18 ms（≈1% CPU） |
| "按一下、录完即出" | 录 1–3 s + 18 ms（端侧）／ + 0.3–1 s 上传（服务端） |
| 逐帧/逐 0.1 s 实时 | **做不到**，模型输入固定 3 s，0.5 s 都不可靠 |
| 多候选 | 每个窗可给 top-5（实测），底层是 6522 类完整分布 |

## 6. 端侧还是服务端

| 判据 | 现状 | 倾向 |
|---|---|---|
| 模型体积 | 49.3 MB（FP32），必须有 FP16/INT8 版本才有机会 | 服务端 |
| 输入要求 | 48 kHz PCM，小程序录音拿到的是编码帧（见 [platform-constraints.md](platform-constraints.md) C1/C2） | 服务端 |
| 单次算力 | 18 ms/窗（4 线程 x86）；手机预计 3–10× | 端侧勉强可行 |
| 首版建议 | **服务端**：端侧只做 VAD + 录音 + 上传 1–3 s | ✅ |

## 7. 主要限制

1. **样本是"录音室级"素材**：xeno-canto 录音本身干净、近距、单物种；真实校园环境信噪比差得多。
2. **风噪是合成的**（1/f 噪声），真实风噪含阵风与低频冲击，可能更糟。
3. 只覆盖 5 个欧洲常见种 + 3 类噪声，**没有多鸟混鸣、雨声、远距离、手机麦克风**的测试。
4. 未评估**中文名映射**与地区物种子集（BirdNET 有 geo filter，可按经纬度裁到 ~3k 类，本项目未启用）。
5. 未测端侧（WASM/TFLite for 小程序）。

## 8. 下一步

1. **接入 geo filter**：按经纬度裁剪候选物种，能直接压低误报（对车流这类假阳性有效）。
2. **VAD + 三窗确认**：连续 3 窗里 ≥2 窗 ≥0.5 才提示，实测误报可显著下降。
3. **补真实场景录音**：手机在校园录 10 段（含风、车、人声），替代合成噪声。
4. **端侧可行性**：把 FP16/INT8 版本转成小程序可用的格式，测 `createInferenceSession` / ort-wasm。
5. **候选 UI**：直接展示 top-3 + 置信度，而不是硬判一个物种（模型本身给的就是分布）。
